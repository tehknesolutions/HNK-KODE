# HNK-KODE Project Chat Baseline — 2026-09-29

Status: architecture baseline

## Product authority

HNK-KODE is the source of truth for the HENUVOKODAN language and its computational/fullstack language family. CODEX-HNK may research, test and derive structural artifacts, but mathematical validity alone does not promote a glyph, lexeme or grammar rule into linguistic canon.

## Current structural baseline

- 12 fundamental HENUVOKODAN keys/letters: phonological/symbolic foundation.
- 432 MF: 72 sectors x 6 layers; generative Glyph Field.
- 463 ACTIVE: 432 MF + 9 external + 22 center; Code Space candidate.
- 504 physical slots: 463 active + 41 reserved.
- HNK40: genesis/validation corpus, not the size of the complete language.
- PATH is the core mechanism for compound glyph formation.

Canonical research form:

GLYPH = START_CELL + PATH + EDGE_SEQUENCE + TRANSFORM

The numbers 432/463/504 are structural/addressing facts of the current model; they must not be assigned arbitrary linguistic or computational semantics merely to satisfy numerology.

## Mandala-HNK Computational Model

Frozen direction:

Mandala-HNK = Encoding + Grammar + Computational Substrate

Identity target:

TEXT <-> AST <-> MANDALA <-> GLYPH <-> HNK-IR

The model may support address space, glyph space, path space, type/operator semantics, composition and transforms only after each semantic mapping is formally specified and tested.

Next formal artifact: MHCM v0.1, covering at minimum:

Cell, Address, Path, Edge, Glyph, Transform, Composition, Type, Operator, Program, plus Mandala <-> AST <-> HNK-IR conversion rules.

## KODESCRIPT / Programming Language

Minimal executable target:

KODE SOURCE -> AST -> HNK-IR -> RUNTIME WORLD

V0 language surface:

world -> entity -> property -> event -> action

Longer-term family can expand toward World + Game + UI + Backend + Data + Network + AI + Automation after the minimal vertical slice is executable and reproducible.

HNK-KODE computational language does not replace the linguistic/spiritual HNK-KODE; it is a computational layer/family within the same project.

GitHub is the source of truth. CI/cloud validation replaces local-PC dependency wherever technically possible. Architecture, research, specs, datasets and tests must be versioned; chat-only decisions are not sufficient project state.
