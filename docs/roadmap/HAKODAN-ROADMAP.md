# haKodan Roadmap — Acceleration V1

Date: 2026-10-02

## North Star

`INTENTION → haKodan → REAL VISIBLE MANIFESTATION`

The roadmap is driven by product evidence, not M-number growth.

## Baseline

Evidence-backed PCI at acceleration start: **55.05%**.

M1–M62 are preserved infrastructure/history. Provenance expansion beyond this point is demand-driven by product/runtime requirements.

## Wave A — Truth & consolidation

Status: **ACTIVE / substantially complete**

- Master acceleration spec.
- Implementation plan.
- Repository audit.
- PCI baseline.
- Product hierarchy locked on haKodan.

Exit: repository truth is explicit enough to prioritize product work.

## Wave B — Product documentation

Status: **ACTIVE**

Deliverables:
- product-first README;
- PDD;
- GDD/experience design;
- current architecture entry point;
- this roadmap;
- changelog/version narrative.

Exit: a new contributor can answer what haKodan is, how it works, what exists and what remains without reconstructing dozens of M-series documents.

## Wave C — Identity & assets

Status: **NEXT**

- inventory approved haKodan/HNK-KODE identity evidence;
- distinguish canonical language glyphs from product UI branding;
- publish design system using approved evidence only;
- create `assets/hakodan/ASSET-MANIFEST.md`;
- normalize/code-wire approved assets;
- mark gaps `UNRESOLVED`.

Exit: product surfaces can use a versioned, non-invented visual system.

## Wave D — Manifestation Golden Path

Status: **PRIMARY ENGINEERING TARGET**

`WORLD → ENTITY → PROPERTY → EVENT → ACTION`

Required chain:
`authoring → canonical semantics → HOM → HNK-IR → target capability → adapter → artifact → runtime → visible result`

Exit: one real manifestation visibly executes.

## Wave E — Studio/authoring

- expose Golden Path through haKodan-centered authoring UX;
- preserve Visual/Standard/Pro convergence;
- inspector + preview/run + meaningful failure states;
- apply approved identity/assets.

Exit: a creator can author and run the Golden Path without manipulating internal IR by hand.

## Wave F — Verification & RC1

- focused tests;
- integration/e2e tests;
- fresh execution evidence;
- provenance binding;
- README quick-start validation;
- PCI recalculation;
- changelog/version update;
- reproducible Acceleration RC1.

Exit: evidence-backed release candidate.

## PCI gates

- 55%: acceleration baseline.
- 60%: consolidated product truth + Golden Path contract.
- 70%: real target + visible Golden Path manifestation.
- 80%: Studio authoring + identity/assets + fresh integration execution.
- 90%: broader target/runtime coverage + robust regression/release path.
- 100%: Acceleration V1 Definition of Done, not an assertion that haKodan can never expand.

## Backlog rule

Any proposed work that does not materially improve execution, usability, verification, documentation/versioning or approved identity is deferred unless it fixes a verified integrity defect.
