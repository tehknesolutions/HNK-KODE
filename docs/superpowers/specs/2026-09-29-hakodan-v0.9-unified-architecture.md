# haKodan v0.9 — Unified Narrative Architecture

**Status:** APPROVED DESIGN / PRE-IMPLEMENTATION
**Date:** 2026-09-29
**Authority:** HNK-KODE / haKodan
**Depends on:** v0.8 Morphological Role System

## 1. Intent
haKodan v0.9 turns typed Kodins into an intent-oriented, multimodal language where narrative source, visual blocks, glyphs, semantic graphs and machine-oriented representations share one semantic identity.

The language MUST accept HNK, PT-BR, EN, or a mix. PT-BR MUST accept accented/ç and normalized spellings.

## 2. Ten foundations
1. Hybrid Contextual Grammar — compact narrative syntax plus optional explicit `{}` / `[]` structures.
2. Intent-Oriented Sentence Architecture — sentences encode intent rather than token order alone.
3. Narrative Flow Object Model — flows/events/conditions are composable objects.
4. Universal Semantic Composition Model — identified nodes can own properties, components, behaviors, events, memory and flows.
5. Universal Manifestation Graph (UMG) — one semantic graph may project to multiple artifacts.
6. Intent Discovery & Progressive Formalization (IDPF) — ambiguity becomes explicit structured discovery.
7. Authority & Provenance Model (APM) — authorship, authority, state, origin and dependencies remain distinct.
8. Reactive Living Graph (RLG) — explicit state/signal/event/dependency/effect causality.
9. Universal Lowering & Transmutation Model (ULTM) — progressive representations from human intent toward machine forms.
10. Glyph–Block–Code Trinity (GBCT) — word, glyph and visual block are projections of one Semantic ID.

## 3. Core pipeline
`ALEF/INTENT → VHK/SOURCE → DISCOVERY GRAPH → SEMANTIC GRAPH → AST → HOM → HNK-IR → MANIFESTATION GRAPH → TARGET IR/ADAPTER → ARTIFACT/MALKUTH`

Alef and Malkuth are internal HNK architectural names here, not external metaphysical claims.

## 4. Sentence model
Every executable sentence MAY expose: `INTENT → AGENT → ACTION → ENTITY → CONTEXT → MANIFESTATION`.
Omitted slots receive explicit parser defaults; they are never invented silently by an AI adapter.

Both forms MUST lower to equivalent semantic structure:
`CREATE Garukan CLASS Teknomage`
`CREATE Garukan { CLASS: Teknomage }`

Token order aids parsing, but Semantic IDs and registered relations own meaning.
## 5. Flow and composition
Initial flow relations: `WHEN`, `IF`, `OTHERWISE`, `EACH`, `WHILE`, `UNTIL`, `THEN`, `PARALLEL`, `SEQUENCE`, `RETURN`, `EMIT`, `MANIFEST`.

`FLOW` is an identified composable object. Context blocks are semantic scopes, not merely punctuation.

Identified node kinds MAY include OBJECT, ENTITY, AGENT, COMPONENT, WORLD, SCENE, SYSTEM, FLOW, EVENT, DOCUMENT, GAME, APP, IMAGE, VIDEO, PROMPT, GDD and PDD, while remaining distinct Type System kinds.

## 6. Manifestation model
`TARGET ≠ FORMAT ≠ ADAPTER ≠ ARTIFACT`.

A single semantic node MAY have multiple manifestations. Adapters decide representation; they do not redefine source semantics.

Execution progression is `INTENT → PLAN → MANIFEST`. Potentially destructive or publishing effects MUST NOT occur merely because an intent was parsed.

## 7. Discovery states
Native lifecycle states: `DISCOVERY`, `PROPOSED`, `CANDIDATE`, `APPROVED`, `CANON`, with lateral states `WATCH`, `REJECTED`, `DEPRECATED`, `SUPERSEDED`, `CONFLICT`.

Initial epistemic operations: `KNOW`, `ASSUME`, `PROPOSE`, `EXPLORE`, `APPROVE`, `REJECT`, `LOCK`.
Generated inference MUST NOT become CANON without the applicable authority gate.
## 8. Authority and provenance
Authority capabilities: `READ`, `PROPOSE`, `EDIT`, `APPROVE`, `CANONIZE`, `LOCK`, `EXECUTE`, `MANIFEST`, `PUBLISH`.

Authorship does not imply authority. Every governed node MAY record source, origin, author/agent, authority, state, evidence, version and dependencies.

`APPROVE` and `CANONIZE` are distinct operations.

Changes use `CHANGE → DIFF → IMPACT → PLAN → APPROVE → MANIFEST` when policy requires approval.

## 9. Reactive Living Graph
Runtime and project reactivity share explicit causal edges: `CHANGE → DETECT → DEPENDENCY → IMPACT → POLICY → PLAN/EVENT → EFFECT → MANIFEST`.

Initial reactive primitives: `STATE`, `SIGNAL`, `EVENT`, `FLOW`, `EFFECT`, `WATCH`.
A change MUST NOT imply an effect unless an explicit dependency/policy permits it.

## 10. Lowering levels
L7 VIBE/NATURAL INTENT
L6 NARRATIVE haKodan
L5 SEMANTIC GRAPH/BLOCKS
L4 AST/HOM
L3 HNK-IR
L2 TARGET IR/BYTECODE/WASM
L1 MACHINE REPRESENTATION
L0 BINARY
Lowering and lifting are different operations. Lifted/reconstructed structures MUST preserve origin markers such as `SOURCE`, `GENERATED`, `LIFTED`, `INFERRED`; reconstruction MUST NOT claim perfect recovery of original intent.

Backends MAY include JS/TS, HTML/CSS/JS, C#, PHP, Python, Phaser, RPG Maker, BYOND, WASM, haKodan bytecode/VM and later native/machine targets. v0.9 defines contracts, not complete support for every backend.

## 11. Glyph–Block–Code Trinity
Every multimodal representation resolves through one Semantic ID.

A registry entry MAY expose HNK/PT-BR/EN lexical forms, `glyphId`/geometry/version metadata and block type/socket/role metadata.

Glyph geometry is not semantic authority. New glyphs remain discovery candidates until Creator Gate.

HNK-MATH MAY parameterize glyph structure, family, position, geometry, symmetry and composition, but numerological/visual metadata MUST NOT silently create compiler behavior.

## 12. Invariants
- HNK/PT-BR/EN/mixed source converges to Semantic IDs before semantic execution.
- PT-BR accented/ç and normalized equivalents preserve identity.
- Text/block/glyph views never create separate semantics.
- Semantic ID/registry outranks morphology, glyph recognition and phonetic resemblance.
- Discovery/inference never silently becomes canon.
- APM gates privileged effects.
- RLG effects require explicit causal/policy edges.
- Existing AST/HOM/HNK-IR architecture is extended, not replaced by a parallel compiler.
- v0.8 and earlier regression suites remain green.
## 13. Reference example
```hakodan
PROJECT Strangeverse {
  CREATE Garukan { CLASS: Teknomage }

  FLOW EnterPortal {
    WHEN Garukan ENTER Portal
      IF Garukan HAS NexusKey
        MANIFEST Nexus
      OTHERWISE
        EMIT NeedKey
  }

  MANIFEST Strangeverse AS {
    GAME USING Phaser
    GDD USING Markdown
    PROMPT USING VibeHaKodin
  }
}
```

The reference example is grammar-design evidence, not a promise that every token already exists in the canonical lexicon.

## 14. v0.9 boundary
v0.9 establishes narrative grammar and contracts for semantic sentences, flow/composition, discovery, authority/provenance, reactivity, manifestation, lowering and multimodal projections. It MUST NOT auto-canonize provisional Kodins, roots, morphemes, glyphs or generated project facts.
